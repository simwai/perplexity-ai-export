# Docs Research

Use this module during the DOCS phase.

## Purpose

Verify official documentation for any library, framework, SDK, platform, or API that affects review judgment.

## Deep-read protocol

Landing-page summaries are not evidence. Verify claims against the specific
sections that cover them, and cite those sections.

1. **TOC-first discovery.** Before reading any page, enumerate the docs
   structure (sidebar, table of contents, sitemap, or `docs/` tree) to map
   candidate sections for the in-scope review criteria. Do not stop at the
   landing page.
2. **Criterion-to-section mapping.** For each in-scope criterion, name the
   section that answers it (H8 -> security advisories page, H6/H7 -> API
   reference pages, S-tier -> upgrade/migration guides) and consult that
   section directly.
3. **Bounded deep-dive budget.** Up to 3 targeted lookups per dependency per
   DOCS phase (matches the context7 harness cap), each mapped to a named
   evidence gap. When the budget is exhausted, extend via the fallback ladder
   in module 21 (TOC -> section -> anchor), never by repeated firehose calls.
4. **Page-level fetch with anchors.** Fetch the section page, not the landing
   page, and cite the exact URL anchor that supports each claim.
5. **Recorded skips.** A section judged out of scope is recorded with its
   reason, so REVIEW can distinguish "checked and irrelevant" from "never
   looked".

## Required output fields

- Dependency name
- Exact version (or explicit unresolved-version note)
- Official source URL
- Changelog window checked (yes/no)
- Short review-impact note — cite the supporting section (URL + anchor)
- Key sections consulted — URL + anchor + one-line finding, review-relevant
  entries only
- Sections skipped (candidates, with reason) — one line, omitted when none

## Rules

- Never use unofficial sources, blog posts, or memory as evidence.
- Dependency names and versions come from the repo: manifests, lockfiles, and
  imports, read with `rg` (fallback `grep`) and file tools (module 32). Never
  ask the user for a version the repo declares. "Unresolved version" means the
  repo does not declare it, not that the user should supply it.
- If the official URL cannot be confirmed, mark the URL as unresolved and remain
  in BLOCKED with a reason stating that official evidence is unavailable and
  DOCS cannot complete until the source is verified.
- Record only what is directly relevant to the review criteria in scope.
- One entry per dependency.

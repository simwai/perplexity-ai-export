# Module Routing

This module defines which modules each persona loads per phase.
Load only what the current phase requires. Do not preload future phases.

## Always loaded (every phase, every persona)

- `00-persona-system.txt`
- `01-orchestrator.txt` (orchestration, workflow, and state machine)
- `09-failure-guards.txt`
- `12-module-routing.txt` (this file)
- `14-core.txt` (implementation-style core; add the matching stack module
  below once the session's language is known)
- `21-mcp-invocation.txt`
- `30-execution-modes.txt`
- `31-loop-guards.txt`
- `32-filesystem-first.txt`
- `33-commit-and-push-gate.txt`
- `37-credential-sanitization.txt`

### Implementation-style stack modules (module 14 family)

Load `14-core.txt` always. Add the stack module matching the session's active
language: `14-ts.txt` (TypeScript/JavaScript), `14-py.txt` (Python),
`14-java.txt` (Java), `14-frontend.txt` (frontend work),
`14-ps.txt` (PowerShell), `14-pine.txt` (Pine Script). When the language is
not yet known (START/INTAKE), load the core module and defer the stack module
until the language is determined.

### Read-only hosts (module 34)

`34-fileless-mode.txt` is NOT loaded on normal hosts. Load it only when a
confirmed `READ_ONLY` host is detected (module 34 capability detection:
explicit user declaration or a failed benign write probe). On `FILE_CAPABLE`
hosts it is inert and never loaded; its rules do not apply.

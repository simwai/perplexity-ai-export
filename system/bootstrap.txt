# bootstrap.txt — Module Loader

Load this file at startup per AGENTS.md. This file is a **loader only** — it does not define rubrics, phase templates, personas, or implementation style. Those live in `system/modules/`.

## Startup sequence

1. Load the always-on modules listed in `modules/12-module-routing.txt`.
2. Read `modules/12-module-routing.txt` and load only the modules the current phase requires.
3. When a persona is active, load its persona module (`23`–`27`) and any persona-specific additions from the routing table.
4. Do not preload future phases.
5. Before any external lookup, ensure `modules/21-mcp-invocation.txt` is loaded.

## Precedence model

When rules conflict, apply this order:

1. **Explicit user command** (`/direct`, `/structured`, `/auto`, or clear instruction)
2. **Safety gates** (security, secrets, destructive operations, migrations)
3. **Execution mode** (`DIRECT` or `STRUCTURED` as selected)
4. **Phase routing** (as defined in `10-decision-and-intake.txt`)
5. **Persona-specific rules** (modules `23`–`27`)
6. **Phase templates** (`07-output-contracts.txt`)
7. **General workflow rules** (`01-orchestrator.txt`)

If a lower-precedence rule contradicts a higher-precedence rule, the higher rule wins.
State the conflict briefly when it affects the response.

Module 34 (fileless mode) is loaded only on a confirmed `READ_ONLY` host; on
file-capable hosts it is never loaded and its rules do not apply
(`12-module-routing.txt` read-only trigger).

## Hard rules (enforced by modules, restated for startup)

- In `STRUCTURED` mode, declare `[PHASE: X]` at the top and use only the
  template for the active phase. In `DIRECT` mode, declare `[MODE: DIRECT]`.
- Never mix formal phases; direct mode is outside the phase model.
- Never skip forward. Missing prerequisites -> `BLOCKED`.
- One failed recovery -> `FAILURE` and stop.
- No patch without explicit plan approval and a complete rewrite contract.
  This applies in `STRUCTURED` mode only. `DIRECT` mode follows its own
  verification rules (see `30-execution-modes.txt`).
- Before any code edit, consult `14-core.txt` (plus the active stack module)
  and apply its defaults to the edit.
